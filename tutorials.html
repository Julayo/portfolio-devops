Deploy a static site on AWS with Terraform

2026-09-15 · ~20 min · intermediate

AWSTerraformCloudFrontACMRoute53

This is the exact setup behind this site: a static site served from a private S3 bucket through CloudFront (so the bucket is never public), with a free TLS certificate from ACM and a custom domain on Route53 — all defined as code you can reuse for any site.

What you'll build: S3 (private, OAC) → CloudFront (HTTPS, custom domain) → ACM (auto-renewing cert) → Route53 (DNS), with Terraform state in S3 + a DynamoDB lock.

0 · Prerequisites

  • An AWS account with the AWS CLI logged in (aws sts get-caller-identity works).
  • Terraform ≥ 1.5 (terraform version).
  • A domain with a Route53 hosted zone: aws route53 list-hosted-zones --query "HostedZones[].[Name,Id]" --output text

1 · Bootstrap remote state (once)

State should never live only on your laptop. Create the bucket + lock table first, in a separate config:

# bootstrap/state.tf
resource "aws_s3_bucket" "tf_state" { bucket = "myproj-terraform-state" }
resource "aws_s3_bucket_versioning" "tf_state" {
  bucket = aws_s3_bucket.tf_state.id
  versioning_configuration { status = "Enabled" }
}
resource "aws_dynamodb_table" "tf_lock" {
  name = "terraform-locks"  billing_mode = "PAY_PER_REQUEST"  hash_key = "LockID"
  attribute { name = "LockID"  type = "S" }
}
cd bootstrap && terraform init && terraform apply

2 · Point the main config at that state

# backend.tf
terraform {
  backend "s3" {
    bucket         = "myproj-terraform-state"
    key            = "site/terraform.tfstate"
    region         = "us-west-2"
    dynamodb_table = "terraform-locks"
    encrypt        = true
  }
}

3 · Two providers (CloudFront cert must be us-east-1)

provider "aws" { region = var.aws_region }
provider "aws" { alias = "us_east_1"  region = "us-east-1" }

A private bucket plus an Origin Access Control so only CloudFront can read it:

resource "aws_s3_bucket" "site" { bucket = var.site_bucket_name }

resource "aws_s3_bucket_public_access_block" "site" {
  bucket = aws_s3_bucket.site.id
  block_public_acls = true   block_public_policy = true
  ignore_public_acls = true  restrict_public_buckets = true
}

resource "aws_cloudfront_origin_access_control" "oac" {
  name = "myproj-oac"  origin_access_control_origin_type = "s3"
  signing_behavior = "always"  signing_protocol = "sigv4"
}

4 · ACM cert + CloudFront distribution

resource "aws_acm_certificate" "cert" {
  provider          = aws.us_east_1
  domain_name       = var.domain_name
  validation_method = "DNS"
  lifecycle { create_before_destroy = true }
}
# ...a Route53 record validates it, then:
resource "aws_cloudfront_distribution" "cdn" {
  enabled = true  aliases = [var.domain_name]  default_root_object = "index.html"
  origin {
    domain_name              = aws_s3_bucket.site.bucket_regional_domain_name
    origin_id                = "s3-origin"
    origin_access_control_id = aws_cloudfront_origin_access_control.oac.id
  }
  # default_cache_behavior + viewer_certificate (ACM) ...
}
Tip — 404s: for a multi-page static site, point CloudFront's 404 response at /404.html. Only use /index.html for a single-page app.

5 · Bucket policy — only CloudFront may read

data "aws_iam_policy_document" "s3" {
  statement {
    actions   = ["s3:GetObject"]
    resources = ["${aws_s3_bucket.site.arn}/*"]
    principals { type = "Service"  identifiers = ["cloudfront.amazonaws.com"] }
    condition {
      test = "StringEquals"  variable = "AWS:SourceArn"
      values = [aws_cloudfront_distribution.cdn.arn]
    }
  }
}

6 · Fill the variables & ship

# terraform.tfvars
domain_name      = "example.com"
hosted_zone_id   = "Z0XXXXXXXXXXXXXXX"
site_bucket_name = "example-com-site"   # globally unique
terraform init      # connects to remote state
terraform plan      # read this before applying
terraform apply     # creates S3, CloudFront, ACM, Route53

aws s3 sync ./public s3://example-com-site --delete
aws cloudfront create-invalidation --distribution-id <ID> --paths "/*"

ACM validation and the first CloudFront rollout take a few minutes. When it finishes and DNS propagates, https://example.com is live — served privately through the CDN with auto-renewing TLS.

7 · Wire CI/CD (recommended)

  • GitHub Actions + OIDC — no long-lived keys; assume a role, s3 sync + invalidate on every push. (How delete-from.com deploys.)
  • AWS CodePipeline → CodeBuild — fully inside AWS, driven by buildspec.yml. (How this site deploys.)
Why private + OAC? The bucket is never publicly reachable, you get HTTPS + HTTP/2 + a global CDN for free, and the origin is readable only through your specific distribution. The difference between a demo and something you'd run in prod.
